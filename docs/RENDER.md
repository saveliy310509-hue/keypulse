# Render.com free — бот 24/7 без сна

Render free подходит, но у него два ограничения, и оба надо закрыть:

| Ограничение Render free | Решение в проекте |
|---|---|
| Сервис засыпает через **15 минут** без входящих запросов | `KEEPALIVE_URL` — бот сам пингует свой `/health` каждые 10 минут |
| Файловая система **эфемерная**: SQLite стирается при каждом рестарте/деплое | `LIBSQL_URL` — база в Turso (бесплатно, SQLite-совместимо) |

Без второго пункта проданные ключи исчезнут при первом же деплое. Это не баг Render, это устройство free-плана.

---

## Шаг 1. Turso (5 минут, бесплатно)

[Turso](https://turso.tech) — облачный libSQL, синтаксис и SQL те же, что у SQLite, поэтому код менять не пришлось.

1. Зарегистрируйся через GitHub: [app.turso.tech](https://app.turso.tech).
2. **Create Database** → имя `keypulse` → регион ближе к Render (например `fra` для Frankfurt).
3. Открой базу → скопируй **URL** вида `libsql://keypulse-USERNAME.turso.io`.
4. **Tokens** → **Create Token** → скопируй (показывается один раз).

Бесплатный лимит: 500 БД, 9 ГБ, 1 млрд чтений строк — для магазина ключей с запасом.

Через CLI, если удобнее:

```bash
curl -sSfL https://get.tur.so/install.sh | bash
turso auth login
turso db create keypulse
turso db show keypulse --url
turso db tokens create keypulse
```

## Шаг 2. Деплой на Render

1. Залей проект в GitHub-репозиторий (`.env` в `.gitignore`, попадёт только `.env.example`).
2. [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint** → выбери репозиторий.
   Render прочитает `render.yaml` и создаст сервис на free-плане.
3. Введи переменные:

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather |
   | `ADMIN_ID` | `8554520733` |
   | `API_SECRET` | длинная случайная строка |
   | `LIBSQL_URL` | `libsql://keypulse-USER.turso.io` |
   | `LIBSQL_AUTH_TOKEN` | токен из Turso |
   | `KEEPALIVE_URL` | `https://keypulse.onrender.com/health` (свой домен Render) |
   | `KEEPALIVE_INTERVAL` | `600` (10 минут) |

   `KEEPALIVE_URL` можно добавить после первого деплоя — Render покажет домен в шапке сервиса.

4. **Create** → ждёшь сборку 2–4 минуты.
5. Логи: **Logs** — должны увидеть:

   ```
   База данных готова (Turso/libSQL)
   Бот @keypulsedbot запущен
   keep-alive включён: https://keypulse.onrender.com/health каждые 600 сек
   ```

6. Проверь `https://keypulse.onrender.com/health` → `{"status":"ok",...}`.
7. Напиши боту `/start`.

## Почему он не засыпает

Render гасит инстанс после 15 минут тишины. Бот пингует собственный публичный URL каждые 10 минут, поэтому тишины не бывает и сервис остаётся живым.

Важные детали:

- пинг идёт **через публичный домен**, а не по `localhost` — только так Render видит входящий запрос;
- первый пинг происходит сразу при старте, дальше — по интервалу;
- если Render всё же перезапустит сервис (деплой, обслуживание), бот поднимется по первому же запросу, база в Turso останется на месте.

Бесплатные 750 инстанс-часов в месяц покрывают круглосуточную работу одного сервиса (744 часа), но запаса почти нет: **не держи на аккаунте второй активный free-сервис**, иначе часы закончатся раньше месяца.

## Дополнительная страховка: внешний пингер

Self-ping спасает от сна, но не поднимет сервис, если Render сам его остановил. Бесплатный внешний пингер решает и это:

1. [UptimeRobot](https://uptimerobot.com) → **New Monitor → HTTP(s)**.
2. URL: `https://keypulse.onrender.com/health`, интервал **5 минут**.
3. Включи уведомления в Telegram (**Alert Contacts → Telegram**) — узнаешь о падении раньше, чем клиенты.

Альтернатива: [cron-job.org](https://cron-job.org) — бесплатный пинг раз в минуту.

## Обновление

`git push` → Render пересоберёт автоматически (`autoDeploy: true`). База в Turso не затрагивается.

## Ограничения free-плана, о которых стоит знать

- **512 МБ RAM, 0.1 CPU** — для бота с запасом; тяжёлые задачи (генерация картинок, парсинг) лучше не вешать.
- **Холодный старт** после остановки — 30–60 секунд, пока Render поднимает контейнер.
- **Нет постоянного диска** — поэтому и нужен Turso. Если однажды перейдёшь на Starter ($7/мес), можно вернуться к SQLite с диском: убери `LIBSQL_URL` и добавь `disk` в `render.yaml`.
- **750 часов/мес** на все free-сервисы аккаунта.

## Если не хочешь Turso

Альтернативы с тем же результатом:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Neon** (Postgres) | бесплатно, без срока | нужен переход на Postgres — код придётся адаптировать |
| **Supabase** (Postgres) | бесплатно 500 МБ | то же самое |
| **Render Starter + диск** | ничего менять не надо | $7/мес |
| **GCP e2-micro** | бесплатно, диск свой | нужна карта, но это VM с постоянным диском |

См. также [FREE_HOSTING.md](FREE_HOSTING.md).
